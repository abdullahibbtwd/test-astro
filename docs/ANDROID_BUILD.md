# Android build reproducibility & release readiness

Branch target: `android/release-readiness`. **Do not deploy or publish from this doc alone.**

The Android tree is **CNG** (Continuous Native Generation): `frontend/android/` is gitignored and regenerated by Expo prebuild / EAS. A clean clone must build without a local `android/` folder or `local.properties`.

## Clean clone → EAS build

From a fresh clone (no `frontend/android/`):

```bash
cd frontend
npm ci
npm run release:check          # expect FAIL until owner inputs are filled — see BLOCKED
npx eas-cli whoami             # must be logged in
npx eas-cli build --platform android --profile preview
npx eas-cli build --platform android --profile production
```

EAS runs prebuild on the builder; you do **not** need `npm run prebuild:android` for cloud builds.

Local native debug (optional, generates gitignored `android/`):

```bash
cd frontend
npm ci
npm run prebuild:android
# Requires local Android SDK — never commit android/ or local.properties
```

## EAS profiles (`frontend/eas.json`)

| Profile | Artifact | Notes |
| --- | --- | --- |
| `development` | APK + dev client | `withoutCredentials: true` (debug signing OK) |
| `preview` | **APK** | Internal distribution; uses EAS credentials when configured |
| `production` | **AAB** (`app-bundle`) | `autoIncrement: "versionCode"`; fails config if API URL unsafe |

`cli.appVersionSource` is `remote` so Play/`versionCode` bumps are tracked by EAS.

## Identity (single source of truth)

**File:** `frontend/config/identity.json`

| Field | Flows into |
| --- | --- |
| `androidPackage` | `app.config.js` → Expo `android.package` → Gradle `applicationId` / namespace after prebuild |
| `scheme` | Expo `scheme` + Android intent-filters / deep links |
| `iosBundleIdentifier` | iOS bundle id |
| `links.*` | In-app legal/support links (fallback) |
| `mapStyleUrls.*` | Release attestation only |

Runtime import: `frontend/src/config/identity.ts`. Preview script reads the same JSON (`Start-Android-Preview.ps1`).

### Owner must change in Google Cloud

1. Android OAuth client: **package name** = `identity.androidPackage`.
2. SHA-1 of the **upload/release** keystore (from EAS credentials — see Signing).
3. (If used) Web client authorized redirect URIs for Supabase Google provider.

### Owner must change in Supabase

1. Auth → URL config: redirect allowlist must include `identity.scheme://**` (and any https app links).
2. Auth → Providers → Google: Web client ID/secret; Android package + SHA-1 if using native Google.
3. Keep publishable keys in EAS env; secret key only on the API host.

Commands to print the release SHA-1 after EAS has a keystore:

```bash
cd frontend
npx eas-cli credentials -p android
# Choose the production profile → view fingerprint / download (store the backup privately)
```

## Signing

- **No keystore in the repo.** `*.keystore`, `*.jks`, `credentials.json` are gitignored.
- Plugin `frontend/plugins/withAndroidReleaseHardening.js` removes `signingConfig signingConfigs.debug` from the **release** Gradle buildType so EAS release signing is not overridden.
- **development** profile uses `withoutCredentials: true` (debug OK).
- **preview/production:** EAS manages the upload keystore (`credentialsSource` remote by default).

### Create / manage keystore via EAS

```bash
cd frontend
npx eas-cli credentials -p android
# Generate a new Android Keystore on EAS, or upload an existing one (owner-held).
```

Prefer **Play App Signing**: Play holds the app signing key; EAS holds the **upload** key.

### Backup procedure (owner)

1. In EAS credentials, download the keystore + store the password/alias in a private password manager (not git, not Slack).
2. Keep a second offline copy (encrypted drive).
3. Record the SHA-1/SHA-256 fingerprints next to the Google Cloud Android OAuth client.
4. If the upload key is lost and Play App Signing is enabled, register a new upload key with Play Console; if Play App Signing was **not** enabled and the key is lost, you cannot update the listing under the same package name.

## Production API URL gate

When `EAS_BUILD_PROFILE=production`, `app.config.js` calls `assertProductionApiUrl` and **fails the build** if `EXPO_PUBLIC_API_URL` is empty, uses `http:`, or contains `sslip.io`.

## release:check

```bash
cd frontend
npm run release:check
```

Fails with a bullet list. Items tagged `[BLOCKED]` need owner inputs (package name, scheme, API domain, map style URLs, privacy/terms/support, consent copy). The agent must not invent those values.

Strict local check of the current shell API URL:

```bash
RELEASE_CHECK_STRICT=1 npm run release:check
```
